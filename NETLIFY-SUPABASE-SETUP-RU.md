# SD — подготовка к Netlify + Supabase

## Что изменено в этой копии
- Удалены неиспользуемые модули и инструменты Teable; аналитический beacon Teable отключён.
- Сохранены страницы, компоненты и расчётные модули исходного проекта.
- API тарифов переведён с Teable на таблицу `public.calculator_settings` в Supabase.
- Сборка больше не запускает `teable/query-tool.mjs`.
- Добавлен `.env.example` без реальных секретов.

## Важно: до публикации
1. В Netlify задайте переменные окружения:
   - `SUPABASE_URL` = `https://cpkebqcwqdwmoecnmneo.supabase.co`
   - `SUPABASE_SECRET_KEY` = секретный ключ проекта Supabase (берётся в Supabase → Settings → API Keys). Хранить только в Netlify, не добавлять в GitHub и не отправлять в чат.
   - `DEVELOPER_PASSWORD` = новый длинный уникальный пароль панели разработчика. Не использовать пароль базы данных.
2. В Supabase в `calculator_settings` должна быть ровно одна строка с полями `id` (UUID), `rules` (json) и `created_at`. В `rules` должен лежать весь JSON-снимок тарифов (объект с `version`, `updatedAt`, `rules`), не только массив `rules`.
3. Политика RLS `public_read_tariffs` с `SELECT` для `public` может остаться. Серверные чтение/запись в этой реализации выполняются секретным ключом только на сервере; публичный ключ в браузер не добавляется.
4. Не публикуйте сайт, пока не проверены вход в `/developer`, загрузка тарифов, сохранение тарифов и расчёты на нескольких тестовых значениях.

## Настройки сборки Netlify
- Build command: `npm run build`
- Publish directory: оставить пустым / значение по умолчанию для Next.js runtime.
- Base directory: корень репозитория (там, где `package.json`).

## Ограничение
Это подготовленная миграционная копия, а не подтверждённый production-релиз. Перед переключением публичной ссылки требуется успешная сборка и ручная проверка в Netlify. Исходное приложение Teable не удалять.
